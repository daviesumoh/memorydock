# 2026-11-14

- Started the pnpm workspace with the console (`memorydock-console`; `console` is a Node core module name, so npm refuses it as a package name).
- The console signs in with AuthKit as a public PKCE client and has no WorkOS API key (see `docs/decisions/2026-11-14-console-keyless-authkit.md`).
- The proxy protects every page by default. `/api/gateway/*` is excluded from the redirect because a fetch call needs a 401, not an HTML sign-in page; the route handler returns that 401 itself.
- The gateway proxy forwards `/v1` only and allow-lists headers in both directions. Its timeout covers the wait for response headers, not the whole response, so SSE streams stay open.
- Set `agentRules: false` in `next.config.ts`; otherwise `next dev` writes an `AGENTS.md` into `console/` on every start.
- Verified against WorkOS Staging in a browser: sign-in through `/callback`, sign-out, and a sign-in started from `/sign-in`. Staging now has the Sign-out URI `http://localhost:3000/` and the Initiate login URI `http://localhost:3000/sign-in`.
- `next dev` moved to port 3001 when 3000 was busy, and sign-in then failed at the callback, which WorkOS only sends to port 3000. The dev script now pins port 3000.
- The signed-in page needs `await connection()` before `withAuth()`. Unsealing the session reads the clock, and with partial prefetching Next.js flagged that as an unstable value in a prefetch.
- Proxied gateway responses are limited to JSON and event streams and carry nosniff and a sandboxing CSP, since they are served from the console's origin.
- Started the Chrome extension skeleton. The public key in the manifest pins the id to `ohlflggckmdbbaooockgncafhecpjboc`; a Playwright test loads the build in Chromium and checks Chrome assigns that id. The private key stays out of the repository.
- The extension reads only `GATEWAY_URL`, `AUTHKIT_DOMAIN` and `CONSOLE_URL` for now. `CLIENT_ID` arrives with sign-in, so no variable is read before code uses it.
- The extension build script is TypeScript run directly by Node, so it is typechecked with the rest of the package and needs no separate build tool.
